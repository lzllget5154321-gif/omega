# Auto-Upgrade Policy：自动升级与替换策略

> **定位**：定义 Omega 何时、如何、在什么条件下可以**自动**升级或替换工具、模型和 Skill，以及何时必须等待用户确认。这是"生态演替"在工程层面的操作规则。

---

## 一、核心原则

```
自动识别 ✅     — 发现新工具、新模型、新版本
自动试用 ✅     — 沙箱测试、基准任务、小范围 canary
自动推荐 ✅     — 展示对比数据、替代方案、影响分析
自动替换 ⚠️     — 低风险任务可以，高风险任务必须确认
强制替换 ❌     — 永远不强制，用户始终有一票否决权
```

---

## 二、风险分级与对应策略

### 2.1 低风险自动域（Auto Domain）

**可以自动执行替换，无需用户确认。**

| 操作类型 | 示例 | 自动替换条件 |
|---------|------|------------|
| **图像草稿生成工具** | DALL-E → Nano Banana Pro（草稿阶段） | 新工具基准评分 > 旧工具 × 1.15 |
| **非关键格式转换** | pdftotext → Marker | 新工具在 ≥10 次任务中成功率更高 |
| **缓存/索引更新** | 向量索引重建 | 新方法更快且不丢失数据 |
| **日志/监控工具** | 内部工具替换 | 不影响任务输出 |
| **批量重命名/文件整理** | 脚本替换 | 可回滚的操作 |

**通知方式**：在周报中记录，不主动通知。

### 2.2 中风险通知域（Notify Domain）

**自动推荐替换，展示对比数据，等待用户确认。**

| 操作类型 | 示例 | 推荐替换条件 |
|---------|------|------------|
| **文献检索工具** | PubMed API → 新学术搜索引擎 | 新工具召回率+精度综合更好 |
| **代码生成引擎** | Claude Code → Codex CLI（或反过来） | 新引擎在 ≥15 次同类任务中更优 |
| **数据分析工具** | Python pandas → R tidyverse（特定任务） | 新工具在该任务类型上更优 |
| **写作辅助** | GPT-4 → Claude 新模型 | 输出质量 + 引用准确性更好 |
| **Skill 库更新** | Skill v2 → v3 | v3 在基准任务上显著更好 |

**通知格式**：
```
🔧 建议升级：[工具/模型名称]
  旧：v2.x（成功率 82%，平均质量 0.75）
  新：v3.0（成功率 94%，平均质量 0.88，成本降低 15%）
  影响任务：[列出受影响的任务类型]
  回滚方案：保留旧版本，一键回退
  [确认升级] [暂不升级] [仅用于新任务]
```

### 2.3 高风险确认域（Confirm Domain）

**仅提醒，不自动替换，必须用户明确确认 + canary 测试。**

| 操作类型 | 示例 | 替换前置条件 |
|---------|------|------------|
| **医学证据评估工具** | GRADE 评级工具替换 | 基准任务 100% 通过 + MEA 审核 |
| **学术写作最终输出** | 写作模型替换 | 盲审测试 + 引用准确性 100% |
| **外部发布/投稿** | 投稿系统操作工具 | 预填测试 + 用户逐字段确认 |
| **付费 API** | 切换到更贵的 API | 成本效益分析 + 用户预算确认 |
| **隐私/敏感数据** | 数据传输服务 | 安全审计 + 用户授权 |
| **核心系统组件** | Docker/Git/Obsidian/Qdrant | canary → staging → production |

**通知格式**：
```
⚠️ 重要升级建议：[工具名称]
  风险等级：高
  旧 → 新：[详细对比表]
  影响范围：[全部受影响的任务/工作流/Skill]
  需要你的确认，因为：[具体原因]
  建议测试：[canary 测试计划]
  [查看详情] [批准测试] [搁置]
```

### 2.4 紧急替换域（Emergency Domain）

**当原工具完全失效时，自动切换到备选，事后通知。**

| 场景 | 自动行为 | 事后通知 |
|------|---------|---------|
| **API 服务下线** | 自动切换到 fallback 工具 | 立即通知 |
| **严重安全漏洞（CVE Critical）** | 立即暂停使用 + 切换到备选 | 立即通知 + 安全报告 |
| **付费墙突然出现** | 切换到免费备选 | 通知 + 展示替代方案 |
| **数据损坏/丢失风险** | 暂停写入 + 保护现有数据 | 紧急通知 |

## 三、自动替换的评分阈值

### 3.1 替换决策矩阵

新工具 X 要替换旧工具 Y，在同一任务类型 T 上：

```
评估维度：
  1. success_rate_X > success_rate_Y × 1.10（成功率至少提升 10%）
  2. output_quality_X − output_quality_Y > 0.05（质量至少提升 5%）
  3. cost_X ≤ cost_Y × 1.20（成本不增加超过 20%）
  4. speed_X ≥ speed_Y × 0.85（速度不降低超过 15%）
  5. risk_level_X ≤ risk_level_Y（风险不增加）

自动替换条件（低风险域）：
  满足 ① + ② + ③ + ④ + ⑤ → 自动替换

推荐替换条件（中风险域）：
  满足 ① + ② + ③ → 推荐替换

仅提醒条件（高风险域）：
  满足 ① + ② → 提醒（即使全部满足也需确认）
```

### 3.2 观察期要求

新工具在成为 preferred 之前的最低观察期：

| 风险域 | 最少使用次数 | 最少时间跨度 | 最少不同任务类型 |
|--------|:----------:|:----------:|:----------:|
| 低风险 | 10 次 | 3 天 | 2 种 |
| 中风险 | 20 次 | 7 天 | 3 种 |
| 高风险 | 30 次 | 14 天 | 5 种 |

## 四、回滚策略

### 4.1 自动回滚触发条件

任何自动替换后，系统持续监控新工具的表现。如果触发以下条件，自动回滚：

```
自动回滚条件（替换后 7 天内）：
  1. 新工具连续 3 次失败
  2. 新工具导致严重错误（数据损坏/输出不可用）
  3. 用户对新工具的输出点了"不满意"2 次
  4. 新工具的 API 成本超出预算 2 倍

回滚操作：
  1. 将旧工具恢复为 preferred
  2. 新工具降级为 candidate（记录回滚原因）
  3. 在 Action Memory 中记录回滚事件
  4. 通知用户（中/高风险域立即通知；低风险域周报记录）
```

### 4.2 回滚日志

```yaml
rollback_event:
  tool: "Nano Banana Pro"
  task_type: "medical_infographic"
  replaced_by: "New-Model-X"
  auto_replaced_date: "2026-05-15"
  rolled_back_date: "2026-05-17"
  reason: "连续 3 次生成包含医学术语错误"
  action: "恢复到 Nano Banana Pro，New-Model-X 降级为 candidate"
  learning: "New-Model-X 的文字准确性不足用于医学术语，更新 Tool Reputation Ledger"
```

## 五、质量模式对升级策略的影响

| 维度 | 标准模式 | 最高质量模式 |
|------|---------|------------|
| **替换阈值** | 1.15× 提升 | 1.25× 提升 |
| **观察期** | 低风险 3 天 / 中风险 7 天 | 全部 14 天 |
| **人工确认** | 低风险自动 | 全部 confirm |
| **回滚准备** | 备选工具就绪 | 备选 + 回滚脚本 + 数据备份 |
| **用户通知** | 周报中 | 每次推荐时 |
