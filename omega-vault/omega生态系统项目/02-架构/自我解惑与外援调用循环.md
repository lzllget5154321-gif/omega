# 自我解惑与外援调用循环

> **定位**：当 Omega 系统在执行任务时遇到自身无法解决的障碍——知识盲区、工具缺失、代码能力不足、方法不确定——它不是停下来等人救，而是像人一样：**自己去查、去问、去调用其他 AI/Agent 解惑，获得答案后继续向下执行。** 这个"受阻→诊断→求助→学习→继续"的闭环，就是自我解惑与外援调用循环（Recursive Help-Seeking Loop）。

---

## 一、为什么需要这个循环

### 1.1 原始动机（来自用户的核心诉求）

> "Omega 系统本身如果无法完成任务，也会像人一样去询问、查询、自己调用 AI 或 Agent 来给自己解惑，并进一步向下发送命令来指挥完成任务。"

现有方法论中，Ability Gap Detector 已经能诊断失败原因（缺工具/缺知识/缺权限/工具不稳定/数据问题），Toolsmith-Lite 能搜索和学习新工具。但还缺一个关键层：

**从"诊断出问题"到"具体找谁求助、怎么求助、求助后如何整合答案继续执行"的完整协议。**

### 1.2 类比：人类研究员面对未知时的行为

```
遇到不会的统计方法
  → 翻教科书 / 查文献 / 搜 Google → 学会了 → 继续分析

遇到没见过的软件平台
  → 读官方文档 / 看 YouTube 教程 / 在沙箱中试 → 搞懂了 → 继续操作

遇到互相矛盾的文献结论
  → 查更多文献 / 做 Meta 分析 / 咨询领域专家 → 形成判断 → 继续写作

代码跑不通
  → 读错误日志 / 查 StackOverflow / 问 Claude Code → 修复 → 继续运行
```

Omega 应该能**自动执行同样的行为**。

## 二、循环总流程

```
任务执行中
  │
  ├── 正常执行
  │     └── 步骤完成 → 进入下一步
  │
  ├── 遇到障碍
  │     │
  │     ├── 步骤 1：障碍检测
  │     │     └── Ability Gap Detector 诊断原因
  │     │
  │     ├── 步骤 2：求助路径选择
  │     │     └── 根据障碍类型 → 映射到求助目标
  │     │
  │     ├── 步骤 3：发起求助
  │     │     ├── 内部求助（查知识库/查 Action Memory/查 Skill Library）
  │     │     ├── 外部工具求助（搜索/下载/试用）
  │     │     ├── 外部 AI 求助（咨询 Claude/ChatGPT/Perplexity/NotebookLM）
  │     │     └── 人类求助（最小必要澄清问题）
  │     │
  │     ├── 步骤 4：答案整合
  │     │     ├── 验证求助结果的可用性
  │     │     ├── 交叉验证（如果多个来源矛盾 → 标注不确定性）
  │     │     └── 将答案转化为可执行的步骤/工具/Skill
  │     │
  │     ├── 步骤 5：重新规划
  │     │     └── Action Brain 用新信息重新规划剩余步骤
  │     │
  │     ├── 步骤 6：继续执行
  │     │     └── 用新路径/新工具/新知识继续推进任务
  │     │
  │     └── 步骤 7：沉淀
  │           ├── 写入 Action Memory（"这个障碍是这样解决的"）
  │           ├── 如果是新工具 → Toolsmith-Lite 封装为 Skill 候选
  │           └── 如果是从外部 AI 学到的知识 → 标注来源 + 置信度
  │
  └── 循环终止条件
        ├── 障碍已解决 → 继续执行
        ├── 循环 3 次仍无法解决 → 向用户报告 + 已完成部分
        └── 用户指示停止 → 保留中间产物
```

## 三、障碍类型 → 求助路径映射

### 3.1 七大障碍类型与对应求助目标

| # | 障碍类型 | 诊断信号 | 求助目标 | 求助方式 |
|---|---------|---------|---------|---------|
| 1 | **缺知识** | 任务中提到未知概念/方法/领域术语 | Researcher / Web Search / Deep Research / 知识库 | 查 wiki/ → 搜网页 → 必要时咨询 NotebookLM |
| 2 | **缺工具** | 所需能力在 Capability Fabric 中无匹配 | Toolsmith-Lite / AI工具生态雷达 | 搜索工具 → 读文档 → 沙箱试用 → 封装 |
| 3 | **缺代码能力** | 任务需要写代码但 Coder Agent 不确定怎么实现 | Claude Code / Codex CLI / StackOverflow / GitHub | 向 Claude Code 提问 → 代码生成 → 沙箱测试 |
| 4 | **缺文献综合** | 任务需要跨多篇文献提取结论但单篇处理不够 | NotebookLM / Deep Research / Researcher | 导入 PDF → RAG 问答 → 综合报告 |
| 5 | **缺统计方法** | 任务涉及不熟悉的统计方法（如你从未用过的模型） | Data Analyst + Researcher + 外部 AI | 文献检索方法学论文 → 向 Claude 咨询选型 → 沙箱试跑 |
| 6 | **缺平台操作知识** | 任务需要操作不熟悉的封闭平台（如某投稿系统） | Computer Use-Lite + 浏览器探索 + 平台文档 | 截图分析界面 → 读帮助文档 → 模拟操作 |
| 7 | **仍不确定** | 经过以上求助后仍无法确定正确做法 | **用户**（最小必要澄清） | 展示已知信息 + 2-3 个候选方案 + 推荐 |

### 3.2 求助优先级（由快到慢、由内到外）

```
第一层：内部知识（毫秒-秒级）
  ├── wiki/ 知识库 → 语义搜索 + 全文搜索
  ├── Action Memory → 查询历史同类任务的处理方式
  ├── Skill Library → 是否有已有 Skill 覆盖
  └── Tool-Affordance Graph → 是否有已知工具

第二层：外部信息（秒-分钟级）
  ├── Web 搜索 → 通过 Perception Mesh 搜索网页
  ├── 学术检索 → PubMed / Semantic Scholar / arXiv
  ├── 代码搜索 → GitHub / StackOverflow / 官方文档
  └── 工具搜索 → PyPI / npm / MCP Hub / GitHub Topics

第三层：外部 AI 咨询（分钟级）
  ├── Claude API → 结构化咨询（方法选型/代码审查/概念解释）
  ├── NotebookLM → RAG 综合（多篇文献同时提问）
  ├── Perplexity → 实时信息查询（需要最新信息的场景）
  ├── ChatGPT / GPT-4 → 备选咨询通道
  └── Deep Research → 需要深度多轮搜索的复杂问题

第四层：工具学习（分钟-小时级）
  ├── Toolsmith-Lite → 搜索→读文档→沙箱试用→封装 Skill
  └── Computer Use-Lite → 浏览器探索封闭平台界面

第五层：人类求助（仅当前四层均无法解决时）
  └── 最小必要澄清问题 → 附带候选方案和推荐
```

**策略**：总是从第一层开始——最快的路径优先。如果内部知识就能解决，不浪费外部 API 调用。只有当低层无法解决时，才逐层升级。

## 四、各类求助的详细协议

### 4.1 缺知识 → 知识库 + Web + NotebookLM

```
障碍：任务中提到"限制立方样条（RCS）分析"，但系统不熟悉这个方法

第一层：内部搜索
  1. wiki/ 搜索 "限制立方样条" OR "RCS" → 无相关页面
  2. Action Memory 搜索 "RCS" OR "restricted cubic spline" → 无历史记录
  3. Skill Library 搜索 → 无覆盖

第二层：外部信息
  4. Web 搜索 "restricted cubic spline analysis tutorial" → 获取 3 篇教程
  5. PubMed 搜索 "restricted cubic spline"[Title/Abstract] → 获取方法学论文
  6. 提取关键信息：RCS 是什么 / 何时用 / R 包（rms::rcs()）/ 结果解读

第三层：外部 AI 咨询
  7. 向 Claude 提问："在 Cox 回归中使用限制立方样条（RCS），
     用 R 的 rms 包，需要哪些步骤？输出代码框架和结果解读要点。"
  8. Claude 返回：步骤说明 + R 代码框架 + 结果解读指南

答案整合：
  9. 将 RCS 知识写入临时概念草稿（标注来源 + 置信度）
  10. Coder 基于 Claude 的代码框架在沙箱中测试
  11. 测试通过 → 继续执行原任务

沉淀：
  12. 如果本次任务成功 → RCS 方法写入 Skill Library（候选）
  13. 如果 RCS 在未来 ≥2 个任务中使用 → 触发创建 wiki/概念/RCS限制立方样条.md
```

### 4.2 缺工具 → Toolsmith-Lite 七步闭环

```
障碍：任务需要从 PDF 中提取表格数据，但 pdftotext 无法保留表格结构

第一层：内部搜索
  1. Tool-Affordance Graph 搜索 "表格提取 + PDF"
  2. Capability Fabric 检查已注册工具 → 无匹配

第二层：外部搜索
  3. Web 搜索 "extract tables from PDF python 2025" → 发现 4 个候选：
     - Camelot (Python, 专门提取表格)
     - Tabula (Java/Python)
     - Marker (支持表格提取)
     - Unstructured.io (通用文档解析)
  4. 比较：Camelot 专门做表格、精度高；Marker 已安装可先试

第三层：Toolsmith-Lite 执行
  5. 读 Camelot 文档 + 安装 (pip install camelot-py[cv])
  6. 沙箱试用：用目标 PDF 测试 → 成功提取 3/4 个表格
  7. 写临时 python 脚本封装调用
  8. 生成 Skill 候选：`pdf-table-extract`
  9. 更新 Tool-Affordance Graph：Camelot → [PDF表格提取, 数据分析]
  10. 更新 Tool Reputation Ledger：Camelot 初始信誉

第四层：继续执行
  11. 用 Camelot 提取 PDF 表格 → 成功 → 继续原任务
```

### 4.3 缺代码能力 → Claude Code / Codex CLI

```
障碍：任务需要写一个 PubMed 批量检索 + 自动下载 PDF 的脚本，
     但 Coder Agent 不确定 PubMed E-utilities 的分页逻辑

第一层：内部搜索
  1. Skill Library 搜索 "pubmed batch search" → 无覆盖
  2. Action Memory 搜索 → 无相关记录

第二层：外部信息
  3. Web 搜索 "PubMed E-utilities pagination retstart retmax" → 获取官方文档

第三层：外部 AI 咨询（Claude Code）
  4. 将需求描述 + PubMed API 文档要点发送给 Claude Code：
     "写一个 Python 脚本，用 PubMed E-utilities 批量检索，
      支持分页（retstart/retmax），自动处理 rate limiting (3 req/s)，
      将结果保存为 CSV。包含错误处理和重试逻辑。"

  5. Claude Code 返回完整脚本 + 使用说明

第四层：验证和继续
  6. Coder 在沙箱中测试脚本 → 用 2 个检索式验证
  7. 测试通过 → 继续执行原任务
  8. 将脚本标记为 Skill 候选（如后续 ≥3 次复用 → 晋升 Active Skill）
```

### 4.4 缺文献综合 → NotebookLM / Deep Research

```
障碍：任务需要综合 8 篇 SGLT2 抑制剂文献写出综述，
     但 Researcher 逐篇处理后，需要跨文献提取共性结论和矛盾点

第三层：外部 AI 咨询（NotebookLM）
  1. 创建 NotebookLM notebook
  2. 导入 8 篇 PDF（从 assets/zotero/<citekey>/ 本地副本）
  3. 提问：
     - "这 8 篇研究中关于 SGLT2 抑制剂肾脏保护的共同结论是什么？"
     - "哪些结论在文献间存在矛盾？"
     - "各项研究的方法学质量有何差异？"
  4. NotebookLM 返回综合回答（基于全部 8 篇的 RAG）
  5. 下载回答为 Markdown

答案整合：
  6. Critic 审查 NotebookLM 回答的事实准确性（抽查关键论断）
  7. Academic Writer 基于综合结果 + MEA 评级撰写综述
  8. 标注"AI 辅助文献综合"

沉淀：
  9. 如果这是常用工作流 → 封装为 Workflow "文献综合→综述"
  10. 记录 NotebookLM 在此类任务上的表现（写入 Tool Reputation Ledger）
```

### 4.5 缺统计方法 → Data Analyst + Researcher + 外部 AI

```
障碍：任务要求做"等时替代模型（Isotemporal Substitution Model）"，
     但系统从未执行过此类分析

第一层：内部搜索
  1. wiki/ 搜索 "等时替代" → 无
  2. Action Memory 搜索 → 无

第二层：外部信息
  3. PubMed 搜索 "isotemporal substitution model physical activity" 
     → 找到方法学论文（Mekary et al., 2009, 2015）

第三层：外部 AI 咨询
  4. 向 Claude 发送：
     "等时替代模型的统计原理是什么？在 R 中如何实现？
      数据：24h 活动行为（睡眠/久坐/LPA/MVPA）+ 健康结局。
      输出：R 代码框架 + 结果解读模板 + 常见陷阱。"

  5. Claude 返回：原理说明 + lmerTest/nlme 代码 + 解读模板

第四层：Data Analyst 执行
  6. 在沙箱中用 Claude 提供的代码框架 + 实际数据试跑
  7. 验证：结果是否合理？置信区间是否正常？
  8. 通过 → 继续原任务

沉淀：
  9. 写入 Action Memory："等时替代模型用 lmerTest 包的 lmer() 实现，
     关键点：成分数据约束（所有行为时间之和=24h）、共线性处理、非线性"
  10. 新方法 → Skill 候选
```

### 4.6 缺平台操作知识 → Computer Use-Lite + 浏览器探索

```
障碍：任务需要向某期刊投稿系统填写信息，
     但系统不知道该投稿平台的具体界面和字段要求

第二层：外部信息
  1. Web 搜索 "X期刊投稿系统 ScholarOne Manuscripts 使用指南"
  2. 找到官方作者指南 PDF

第三层：Computer Use-Lite 探索
  3. 浏览器打开投稿系统（用户已登录状态）
  4. 截图 + DOM 分析界面结构（字段名称、必填项、下拉选项）
  5. 比对作者指南 → 确认每个字段的填写要求
  6. 生成操作计划："第 1 步填标题，第 2 步填摘要，第 3 步选文章类型..."

第四层：预填并等待用户确认
  7. 逐字段预填（不提交）
  8. 生成预填预览截图
  9. 标注未填项和不确定项
  10. 呈现给用户 → 用户确认后手动点击 Submit
```

### 4.7 仍不确定 → 最小必要澄清

```
前置条件：经过内部知识 → 外部搜索 → 外部 AI → 工具学习 全部尝试后，
          仍无法确定正确答案或最佳方案

最小必要澄清协议（详见 [[Tool-Agent Router：最佳工具与最佳执行者选择器]] 7.2 节）：

1. 必须附带 ≥2 个具体候选方案
2. 必须附带推荐方案 + 理由
3. 必须附带预估时间
4. 必须允许用户一键确认（"就按你的推荐来"）
5. 一次只问一个问题

示例：
  "关于这个 Meta 分析的效应量选择，我做了以下调查：
   - 选项 A：标准化均值差（SMD, Hedges' g）— 适合连续变量，可跨研究比较
   - 选项 B：比值比（OR）— 适合二分类结局，但你的 5 篇研究都是连续变量
   
   建议选 A，因为全部纳入研究的结局都是连续变量（eGFR 变化值）。
   你确认吗？[按 A] [换 B] [你再查查别的]"
```

## 五、外部 AI 咨询协议规范

### 5.1 咨询请求格式

向外部 AI 发起咨询时，Omega 必须遵循标准化格式：

```yaml
consultation_request:
  requester: omega_ecosystem
  task_id: omega-task-2026-0515-007
  target_ai: claude_api  # 或 notebooklm / perplexity / chatgpt
  context:
    what_im_doing: "正在为 8 篇 SGLT2 抑制剂 RCT 做 Meta 分析"
    what_i_need: "不确定应该用固定效应还是随机效应模型"
    what_i_know: "8 篇研究的 I² 统计量范围在 45-72%，各研究样本量和人群特征有差异"
    what_ive_tried: "已读 Cochrane Handbook 第 10 章，但各研究异质性处于灰色地带"
  questions:
    - "基于 I²=45-72%，应该选固定效应还是随机效应？"
    - "如果选随机效应，DL 法和 REML 法在什么情况下差异大？"
    - "是否有敏感性分析可以验证选择的稳健性？"
  output_format: structured  # 期望结构化回答
  urgency: normal  # normal / high / low
```

### 5.2 答案处理规范

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | **接收答案** | 完整保存外部 AI 的原始回答 |
| 2 | **标注来源** | "此建议来自 {AI名称}，{时间}，置信度待验证" |
| 3 | **交叉验证** | 如果同时咨询了多个 AI → 比对一致性，标注分歧 |
| 4 | **Critic 审查** | Critic 检查回答的逻辑和事实基础（抽查关键论断） |
| 5 | **置信度标注** | 高（多个来源一致 + 与已知知识吻合）/ 中 / 低 |
| 6 | **整合执行** | 将经验证的答案转化为可执行步骤 |
| 7 | **记录沉淀** | 写入 Action Memory → 未来同类问题不再需要外部咨询 |

### 5.3 多源咨询的分歧处理

当多个外部 AI 给出矛盾建议时：

```
场景：Claude 推荐固定效应，Perplexity 推荐随机效应

处理：
  1. 标注矛盾："外部 AI 建议存在分歧：
     - Claude: 固定效应（理由：I² 在可接受范围）
     - Perplexity: 随机效应（理由：研究间有临床异质性）"
  
  2. 升级策略：
     - 查阅更高权威来源（Cochrane Handbook / 方法学论文）
     - 如果仍不确定 → 向用户报告分歧 + 推荐方案 + 理由
  
  3. 标注到 Outcome Package：
     "Meta 分析模型选择：最终采用随机效应模型（REML 法）。
      注：外部 AI 对此存在分歧，最终选择基于 Cochrane Handbook 建议
      和敏感性分析结果。"
```

## 六、循环的安全边界

### 6.1 循环深度限制

为防止无限循环（不停求助→不停失败→继续求助）：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| **最大循环深度** | 3 轮 | 同一个障碍经过 3 轮求助仍无法解决 → 停止并向用户报告 |
| **最大总求助时间** | 15 分钟 | 单障碍的总求助时间超过此值 → 暂停并报告 |
| **最大外部 API 调用** | 10 次/障碍 | 防止 API 费用失控 |
| **最大工具试用** | 3 个/障碍 | Toolsmith-Lite 最多试用 3 个候选工具 → 选最优 |
| **循环间隔** | 30 秒 | 同一求助目标的最小间隔（防止重复调用同一 API） |

### 6.2 禁止的求助行为

| 禁止行为 | 原因 |
|---------|------|
| 向外部 AI 发送用户的敏感凭证或私钥 | 安全边界 |
| 将用户的未发布草稿全文发送给外部 AI | 隐私边界 |
| 基于外部 AI 的单一建议直接修改核心系统配置 | 需要 Critic + 用户双重确认 |
| 循环求助导致 API 费用超过预设预算 | 成本控制（应提前估算并告知用户） |
| 向外部 AI 描述用户系统的完整架构 | 安全边界（只发送与问题相关的必要上下文） |

### 6.3 求助日志透明化

每次求助都记录到 Action Memory：

```yaml
help_seeking_log:
  task_id: omega-task-2026-0515-007
  obstacle: "不确定 Meta 分析的效应模型选择"
  cycle: 1  # 第 1 轮求助
  path_used:
    - layer_1: [wiki/搜索, action_memory搜索, skill_library搜索] → 未解决
    - layer_2: [web搜索] → 找到 Cochrane Handbook 相关章节
    - layer_3: [claude_api咨询] → 获得模型选择建议
  result: resolved  # resolved / escalated_to_user / failed
  answer: "采用随机效应模型（REML 法）"
  answer_confidence: high
  sources: ["Cochrane Handbook Ch10", "Claude API 2026-05-15"]
  time_spent: 4.2min
  api_calls: 1 (Claude API)
  cost: $0.03
```

## 十、核心原则总结

1. **不问"能不能做"，只问"怎么做"**——障碍触发的是求助，不是放弃
2. **先内后外、先快后慢**——总是从最快的内部知识开始，逐层升级
3. **求助结果标注来源和置信度**——外部 AI 的建议不是真理，是参考
4. **每次求助都是一次学习**——解决了就沉淀，下次不用再问
5. **循环有边界**——3 轮搞不定就停下来问人，不要无限求助
6. **最小必要澄清**——问人的时候带上方案和推荐，不把决策负担抛回去
7. **透明记录**——所有求助都写入 Action Memory，可追溯、可复盘
